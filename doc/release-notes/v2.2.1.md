# RASTER Music Tracker 2.2.1 – sharp on Qt6, fits the screen

**RMT 2.2.1 fixes the size of the window on screens scaled to 150%, a side effect of the sharper rendering of [2.2](https://github.com/gianlucarenzi/RASTER-Music-Tracker/releases/tag/v2.2).**

The tracker itself is the same as in 2.2: same songs, instruments and settings. As always, **please tell me how it works for you** by opening an [issue](https://github.com/gianlucarenzi/RASTER-Music-Tracker/issues).

## Downloads

| System | Package | How to start it |
|--------|---------|-----------------|
| Linux x86_64 (Debian 11, Ubuntu 20.04 and newer) | `RMT-Linux-x86_64.AppImage` | `chmod +x RMT-Linux-x86_64.AppImage`, then run it (needs `libfuse2`; without it add `--appimage-extract-and-run`) |
| Windows 64 bit | `RMT-Windows-x64.zip` | unzip it anywhere and run `Rmt.exe`; it is not signed, so Windows may ask to confirm |
| macOS 12 or later, Apple Silicon | `RMT-macOS-arm64.dmg` | drag `RMT.app` to Applications; it is not notarized, so the first time open it with right click → Open |
| macOS 12 or later, Intel | `RMT-macOS-x86_64.dmg` | as above; also runs on Apple Silicon through Rosetta 2 |

Everything the program needs is inside each package.

## What changed

- **Whole scale factor, rounded down**: 2.2 rounded the scale of the desktop to the nearest whole number, so 150% became 2 and the 1280x800 window no longer fitted a 1920x1080 screen. The factor is now rounded down (1.1 becomes 1, 1.5 becomes 1, 2 stays 2), as Qt5 did: the tracker stays sharp and the window fits. On a screen scaled to 150% the interface is therefore drawn at the normal size. Checked on Linux with X11 at 96, 106, 120 and 144 dpi, where the pattern grid is identical to the Qt5 one; not tried on Windows and macOS.
